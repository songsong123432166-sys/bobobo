# 摄像头检测运行逻辑

本文说明健康提醒程序中摄像头检测的触发条件、识别流程和状态联动逻辑。

## 触发条件

摄像头不会一直工作。后台服务每 5 秒检查一次状态，但只有满足以下条件时才会真正打开摄像头：

- 设置项 `detection.camera_enabled` 为 `true`。
- 键盘鼠标空闲时长达到 `detection.camera_idle_threshold_seconds`，默认 60 秒。
- 距离上一次常规摄像头检测已超过 `detection.camera_interval_seconds`，默认 60 秒。

如果键盘或鼠标在 60 秒内有操作，程序会直接认为用户正在使用电脑，并重置久坐计时，不打开摄像头。

## 常规离席检测

常规检测流程如下：

1. 键鼠空闲超过阈值后，服务调用 `CameraPresenceDetector.check()`。
2. 检测器打开默认摄像头 `camera_index=0`。
3. 单次检测最多采样 3 帧，避免第一帧曝光或对焦不稳定导致误判。
4. 每帧会转成灰度图，限制检测宽度，并做灰度均衡。
5. 同时使用 OpenCV 正脸模型和侧脸模型检测。
6. 任意一帧检测到人脸，即认为 `person_present=True`。
7. 所有有效帧都没有检测到人脸，即认为 `person_present=False`。

离席判定不是一次没检测到人就立刻生效。程序会累计未检测到人的次数：

- `detection.camera_confirm_misses` 默认 3 次。
- 连续达到该次数后，才将状态标记为离席。

这样可以减少眨眼、转头、短暂遮挡造成的误判。

## 摄像头不可用时

如果 OpenCV 未安装、摄像头打不开、帧读取失败或模型不可用，程序不会崩溃。

此时会回退到键鼠空闲判断：

- 如果键鼠空闲时长达到 `detection.idle_after_seconds`，默认 300 秒，则标记为离席。
- 否则保持当前状态。

## 站起提醒后的检测

久坐提醒弹出后，站起提醒本身不需要用户点按钮。

程序会启动一个短期观察窗口：

- 持续时间由 `detection.stand_watch_duration_seconds` 控制，默认 180 秒。
- 检测间隔由 `detection.stand_watch_interval_seconds` 控制，默认 20 秒。

在这个窗口内：

1. 每到检测间隔，程序调用一次摄像头检测。
2. 如果检测到电脑前无人，说明用户已经起身离开。
3. 程序自动记录一次起身，并重置久坐提醒计时。
4. 如果 3 分钟内一直检测到有人或摄像头不可用，则本轮站起确认超时，不记录起身。

## 状态灯逻辑

摄像头检测会和键鼠检测共同影响主界面状态灯：

- 绿灯：`using`，电脑正在使用。
- 黄灯：`away_short`，检测到离席但未超过红灯阈值。
- 红灯：`away_long`，离席超过 `detection.away_red_after_seconds`，默认 1200 秒。

当检测到用户回来后，程序会：

- 将状态恢复为 `using`。
- 重新开始久坐计时。
- 如果中央弹窗开关开启，则弹出离席原因选择窗口。

## 中文路径兼容

OpenCV 在部分 Windows 环境下无法从中文路径加载 Haar 模型文件。

程序会在检测到模型路径可能不兼容时，将模型缓存到 ASCII 路径后再加载：

- `C:\ProgramData\HealthTrayReminder`
- `C:\Windows\Temp\HealthTrayReminder`

如果缓存失败，摄像头检测会安全降级，不会导致程序退出。

## 性能说明

当前摄像头检测属于轻量级本地检测：

- 不联网。
- 不上传图片。
- 不保存摄像头画面。
- 不持续占用摄像头。
- 默认空闲后每 60 秒短暂打开一次摄像头。
- 单次最多读取 3 帧，并限制检测图像宽度。

因此对 CPU 和电量影响较低，适合作为托盘后台程序长期运行。

## 已知限制

当前实现使用 OpenCV Haar Cascade 模型，优点是轻量、无需额外大模型文件，缺点是识别稳定性有限。

容易识别失败的情况：

- 光线太暗或强背光。
- 脸离摄像头太远。
- 侧脸角度过大。
- 戴口罩、遮挡脸部。
- 摄像头画面模糊。

如果以后需要更高准确率，可以考虑替换为 OpenCV DNN、MediaPipe 或其他轻量人脸/人体检测模型，但会增加模型体积和一定 CPU 占用。
